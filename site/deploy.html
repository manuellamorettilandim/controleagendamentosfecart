Render + host central

Relay público

  1. Crie um Web Service no Render a partir deste repositório.
  2. Use o render.yaml; o build é npm ci && npm run build e o start é npm run relay.
  3. Gere um segredo forte para o túnel. No Render, configure somente RELAY_AGENT_TOKEN_SHA256, o SHA-256 desse segredo.
  4. Após o deploy, teste https://SEU_HOST/healthz. O /readyz ficará 503 até o host conectar.

Painel administrativo

Configure no Render somente SUPABASE_URL e SUPABASE_PUBLISHABLE_KEY. Aplique a migration supabase/migrations/20260812000000_codex_admin.sql, crie o usuário owner no Supabase Auth e configure SUPABASE_SECRET_KEY apenas na máquina central antes de rodar npm.cmd run admin -- bootstrap --email seu-email. A secret key não entra no Render.

Host central

codex login
$env:RELAY_URL = "wss://SEU_HOST.onrender.com"
$env:RELAY_AGENT_TOKEN = "O_MESMO_SEGREDO_USADO_NO_HASH"
npm.cmd run host

Deixe essa máquina ligada. O host agent reconecta após reinícios do relay e ressincroniza os dispositivos ativos.

Render Free

O plano Free pode dormir após inatividade e usa filesystem efêmero. O relay não guarda a fonte de verdade; por isso a lista volta do host central depois da reconexão. Conexões WebSocket também podem cair quando uma instância é substituída.

Checklist

  • URL pública usa https:///wss://.
  • O hash do segredo está no Render; o segredo bruto está somente no host.
  • Não há CODEX_HOME, auth.json ou API key em variáveis do Render.
  • O host responde 200 em /readyz antes de testar o CLI.
  • Existe um procedimento local para parar o host e revogar tokens.

Referências: Render Free, Render WebSockets e OpenAI App Server.
